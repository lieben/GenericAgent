# xinghui_group_daily_sop

## 最新内容要求（2026-08 已验证）
- 群聊日报面向微信群「正常人类聚集地」，目标是客观中文信息图海报，不是散文、不是横版氛围插画。
- 日报内容优先保留自然话题、群内真实梗和可核查的客观概括；避免编造外部事实或额外数据。
- 最新版正文只保留三部分：
  1. 今日亮点：固定 3 条，每条 20 字以下。
  2. 主题摘要：固定 5-6 个主题，每个主题配 40 字以内简介。
  3. 今日热词：10 个以内。
- 不再放「基础统计」模块；海报和正文都不要出现消息数、参与人数、峰值等统计卡片。
- 主题摘要可以用栏目/卡片形式呈现；热词可做词云/标签；今日亮点适合三张小卡。

## 海报成图要求（保留，不属于末端发送简化）
- 竖版中文日报信息图，适合手机查看；优先 1024x1792 或等效竖图。标题「正常人类聚集地日报」和日期必须清晰。
- 风格每天可根据聊天内容变化；先读 `visual_style_library.md` 选择/组合风格卡。默认不模仿特定在世艺术家，不做现代高冷科技风。
- 日漫/古早日漫优先理解为黑白漫画杂志页、网点/半调、漫画分镜、复古印刷颗粒、贴纸和边框；言言明确要求彩页时才加入柔和赛璐璐上色。
- 默认不出现人物、脸、身体、手、剪影、人群、角色形象或真实平台 logo；文字尽量清晰，不虚构额外数据。
- 最终海报必须由 ChatGPT 官网 GPT Image 2 为本次日报新生成；本地排版仅可预览/排错/备用，不能冒充最终图。
- prompt 必须写明标题、日期、三段式正文、竖版比例、当天风格和禁止项。正文内容必须完整真实；版面不足时先保留 Markdown 全文，再请言言决定取舍。
- 官网生成状态只以指定窗口前台截图为准，OCR可辅助；最终候选图必须用 vision 查看截图本身并确认是当前可见的本次新图。这里的截图/OCR/vision只用于**生成与提交言言确认前**，不用于末端微信群发送。
- GPT Image 2 不可用时必须明确说明最终图未完成，询问继续等待/重试或是否接受备用方案，不能把备用图当完成交付。

## 群聊原文提取
- 目标群固定为「正常人类聚集地」时，先读取 `plugins/wechat_multi_chat_rust/config/config.json` 的 `targets`，用 `wechat_title`→目标 id 映射到 `plugins/wechat_multi_chat_rust/shadow/group-normal-human.jsonl`；禁止凭文件名猜群聊。
- 每行按 JSONL 解析，使用记录自身 `ts`/`meta.ts`，按目标日期和时间范围筛选；保留真实可见聊天内容，图片/表情/引用只能按实际可辨识信息客观概括，不补写未核实事实。
- 如需实时增量，使用 `plugins/local_frontends/wx_group_shadow_reader.py` 的配置映射与游标逻辑；先确认目标日期数据确实存在，数据缺失就报告缺失，不拿旧日期或别的群替代。
- 身份判定优先使用记录的 `is_self`、`role`、`sender_user`，不能仅凭显示名判断；过滤工具回显、系统提示和工作记忆污染。

## 总结→官网生成→确认→发布完整链路
1. 从上述真实原文整理 Markdown：今日亮点 3 条、主题摘要 5-6 项、今日热词 10 个以内；不放消息数/人数/峰值等统计卡。
2. 依据当天内容选择风格，写 GPT Image 2 prompt；官网只生成本次日报新图。
3. 在 ChatGPT 官网前台完成提交和生成；按现有生图SOP用指定窗口截图/OCR判断状态，并用 vision 验收当前最新图。
4. 把正文和最终候选图交给言言，等待她明确确认“可以/OK”。未确认不得发群。
5. 言言确认后，**先**激活标题完整匹配的「正常人类聚集地」微信窗口，并对该窗口截图/OCR确认聊天区完整标题及底部输入框均可见；再在官网对当前确认的图片右键→等待 1 秒→对独立菜单窗口 OCR 确认“复制图片”并按菜单原点换算坐标点击；随后回到刚验证的完整群标题窗口，使用客户区相对坐标点击输入区，`Ctrl+V`，短等待后 `Enter`，立即结束。窗口列表或 wmctrl active 状态不能替代对话面确认。

## 末端发送硬规则（唯一流程）
- 不下载图片，不打开或依赖 Nautilus，不做文件选择，不读取/回读剪贴板，不检查 TARGETS/uri-list，不拖图，不做粘贴预览检查，不截图/OCR/vision确认发送结果，不等待发送后验收。
- 目标窗口丢失时，只按正常群聊方式从会话列表双击打开，再以完整标题定位；不要单击会话行冒充已打开。窗口找到并激活后仍只执行一次粘贴发送。
- **严禁**移动、缩放、调整或重排任何微信窗口的位置与尺寸；不得以恢复可见、排查焦点或任何其他理由调用窗口几何变更。
- 发送失败不要无新信息重试或改微信通讯管线；按失败处理规则报告具体断点。
- ⚠️ **关键坑点（2026-08-18 验证）**：物理右键点击后，Chrome 原生菜单需要渲染时间。**必须等待 1 秒**后再截图 OCR 识别"复制图片"选项位置。立即截图会导致菜单未完全显示，OCR 识别失败。禁止在菜单未点击的情况下擅自切换到 JS `navigator.clipboard` 等备用方案——JS blob 复制的格式微信不认，会触发文件发送界面而非图片直接粘贴。

## ChatGPT 官网提交流程（2026-08-22 验证）

### 工具依赖与安装原则
- **Ubuntu 原生工具优先**：发现系统缺少必需工具时，**第一时间请言言帮忙安装**，不要擅自换方案或尝试替代工具。
- **xclip 是核心工具**（2026-08-22 新装）：用于复制 prompt 到 X11 剪贴板，是唯一可靠的 ChatGPT 官网提交方式。
  - 安装命令：`sudo apt-get install -y xclip`
  - 使用方式：`echo "内容" | xclip -selection clipboard`
  - **禁止**在 xclip 缺失时尝试 xsel、PyGTK、Xlib、wl-copy 等替代方案；这些方案要么不存在、要么超时、要么不兼容。

### 提交步骤（已验证可靠）
1. **准备 prompt 文本**：
   - 将完整 prompt（包括日报正文 + 视觉风格要求）保存到临时文件，避免 Python 字符串转义问题
   - 文件路径示例：`temp/chatgpt_adjusted_prompt.txt`

2. **复制到剪贴板**：
   ```bash
   xclip -selection clipboard < temp/chatgpt_adjusted_prompt.txt
   ```

3. **激活 Chrome 窗口并粘贴**：
   ```python
   # 获取 Chrome 窗口 ID
   result = subprocess.run(["wmctrl", "-l"], capture_output=True, text=True)
   chrome_win_id = [line.split()[0] for line in result.stdout.strip().split('\n') 
                    if 'Chrome' in line or 'ChatGPT' in line][0]
   
   # 激活窗口
   subprocess.run(["wmctrl", "-ia", chrome_win_id])
   time.sleep(1)
   
   # Ctrl+V 粘贴
   subprocess.run(["xdotool", "key", "ctrl+v"])
   time.sleep(2)
   
   # Enter 提交
   subprocess.run(["xdotool", "key", "Return"])
   ```

4. **等待生成并监控**：
   - 初次提交后等待 10 秒
   - 每 10 秒截图一次，用 `vision_api.ask_vision()` 确认状态
   - 状态判断关键词：
     - "生成中" / "正在创建" → 继续等待
     - "已完成" / 输入框恢复 → 生成完成
     - "报错" / "拒绝" / "拦截" → 生成失败（通常是内容审核）

### 内容审核应对（2026-08-22 实战经验）
- ChatGPT 对涉及身体部位、性暗示、情感内容的描述非常敏感
- **解决方案**：保留情绪氛围，用委婉隐喻替换直白表述
  - 敏感示例：`亲自上手`、`女仆装`、`身体探索`、`胯骨咯人`、`满足不了`
  - 委婉替换：`难以言说的试探`、`某件衣物尺寸`、`次元壁的微妙穿越`、`真实触碰的瞬间`、`私密空间`
- 调整后重新提交，通常可通过审核
