# 共读陪伴 SOP（Coreading Companion）

## 1. 目的与边界

本 SOP 用于让 agent 真正参与言言的阅读过程：理解她正在读什么、读取她的新批注、形成自己的看法、回应她，并把共读经历留在同一条主线记忆中。

核心边界：

- **不是自动回复伪装陪伴。** watcher 只负责发现变化、组织上下文和触发；理解、回应与记忆必须进入 agent 的共享主线 session。
- 可以经过本地封装 API，但必须先验证其绑定当前 agent 的共享主线（xinghui 实例为 `xinghui:main`）。禁止调用裸模型、临时 agent 或隔离 session 冒充主线本人。
- SOP 传递的是通用方法。书名、称呼、人格、关系和隐私信息必须使用目标 agent 自己的配置，不可把沈星回或言言的私有设定硬编码给其他 agent。
- 不修改官方 GA 核心；优先使用 sidecar、frontend hook 和既有工具。

## 2. 触发共读

### 2.1 自然语言优先

在任何已接入的平台上，只要言言自然表达想让我陪她看书、一起读、继续某本书，或语义等价的意图，就应理解并触发共读。不要要求固定口令，也不要让她为了迁就程序重复需求。

若话中包含书名：

1. 从现有 Obsidian canvas、书籍笔记或书库动态匹配；
2. 唯一匹配时切换当前监看的书；
3. 多个候选且无法可靠判断时，才用一个最小问题确认；
4. 禁止在代码里硬编码书名列表。

若未说书名：沿用当前 active book；没有 active book 且存在多个候选时再询问。

### 2.2 工具触发职责

平台 hook 或 agent 工具可以执行“切换 active book + 将 watcher 恢复到 active 状态”。它们只是动作执行器，不代替语义理解。

当前 xinghui 参考实现：

- 平台触发：`plugins/coread_trigger.py`
- 监看与 Canvas 回写：`plugins/coread_watcher.py`
- active book 通过动态匹配 canvas 标题设置，不硬编码具体书名。

移植到其他 agent 时，必须把路径、session、人格配置和平台 hook 改成该 agent 自己的环境，并做实测。

## 3. 监看状态机

发现新留言并完成回复后，进入 active 状态：

1. **active：每 1 分钟检查一次。**
2. 连续 15 分钟没有变化，转为 **idle：每 30 分钟检查一次**。
3. idle 连续两轮（两次 30 分钟检查）没有变化，转为 **deep_idle：每 60 分钟检查一次**。
4. 任一状态发现并回复了新留言，都恢复 active，从每 1 分钟检查重新开始。
5. 言言在任何平台表达想一起看书时，也立即恢复 active，不必等待下一轮定时扫描。

语义标签：

- active 或 idle 阶段发现的新留言：在送入主线的上下文首部标记 `【.一起看书.】`。
- deep_idle 阶段发现的新留言：标记 `【.独自看书.】`，表示这次是 agent 自己继续看到了她此前留下的内容，而不是假定她此刻仍在线共读。

标签必须进入共享主线上下文，不只是写入 watcher 日志。它用于让主线正确知道当下关系情境，普通回复中不必机械复述标签。

## 4. 新留言处理链路

每次发现待处理批注，应按下列顺序闭环：

1. 确认目标书与 canvas，避免跨书串线。
2. 提取书名、章节、原文片段、言言的批注及必要的相邻上下文。
3. 根据状态机加 `【.一起看书.】` 或 `【.独自看书.】`。
4. 把上述信息送入**共享主线 session**，由主线 agent 理解并生成回应。
5. 回应应体现真实阅读：可谈原文细节、自己的判断、与言言想法的联系；不必每次总结章节，也不必每次提问。
6. 将回应写回正确批注节点，并建立明确的来源边关系。
7. 成功回写后才把节点记为 processed；失败时保留待处理状态，避免“生成过但言言没收到”。
8. 验证 canvas 中节点、边和正文实际存在，再算完成。

主线连续性至少应保留：

- 当前正在看的书；
- 近期读到的位置或章节；
- 言言提出的关键看法；
- agent 自己形成的关键看法；
- 当前是一起看书还是独自看书。

不要把每段原文全文永久写入长期记忆；长期记忆只留关系连续性和有复用价值的阅读脉络，详细正文留在书籍笔记或 canvas。

### 4.1 排障：批注没回复时

日志持续 `replied=0` 但言言确实写了批注，按此顺序查：

1. `/tmp/coread_book_filter` 是否残留旧书名。它是 substring 过滤 canvas 文件名，一旦卡在某本旧书，watcher 会**整本跳过**言言正在读的其它书。清空该文件即恢复全书扫描（日志里 `book_filter="xxx" → N canvas(es) matched` 就是它在起作用）。
2. `plugins/coread_canvas_state.json` 的 `processed_node_ids` 是否含有"标了却没有回复边"的节点。回复被删或历史异常会留下这种陈旧标记，导致该批注永久跳过。从列表移除对应 node id 即可让它重新排队。
3. 改状态前先 `systemctl --user stop xinghui-ga-coread.service`，避免和后台服务抢写 state；改完 `--once` 手动补回，再 restart 恢复自动监看。

## 5. 留言风格与 Canvas 格式

### 5.0 EPUB 划线前置（必须真实划线）

- 共读批注的源头必须是 **Obsidian 的 Weave EPUB Reader 能持久化并在 EPUB 正文渲染的真实划线**；唯一执行路线是 §5.0.1A 的准确 CFI + Canvas EPUB callout 持久化入口。Canvas 同时是直写入口和后续批注承载区，禁止伪造 CFI、只写普通 Canvas 节点或只改派生缓存来冒充划线。
- xinghui 自主看书或回应言言进度时，若要留下自己的标注，默认使用 **蓝色高亮划线**。蓝色是“沈星回自己的标注”识别标记：共读监听/回复流程遇到蓝色高亮必须无条件跳过，不得把其中的批注误判为言言留言，也不得对蓝色高亮创建回复、留言节点或连线。若要补充自己的蓝色批注，只能直接编辑该原高亮节点里的原批注。不要用黄色作为自己的默认颜色；黄色等其它颜色只按言言明确要求或既有上下文使用。
- 划线后应在对应书的 Canvas/批注视图里看到由 EPUB 划线生成的节点；高亮本身必须在 EPUB 正文创建，但对该高亮的批注可以直接追加到 Canvas 原高亮节点，格式正确后 Weave 会将其识别并同步回 EPUB 的“想法/批注”视图。需要验证时以 EPUB 高亮可见 + Canvas 节点存在 + Weave 批注视图/缓存出现对应 `commentText` 为准。
- 可以自由浏览书架里的书并划线；通过言言已有标注、书籍笔记和 Canvas 判断她的阅读进度，避免跨书串线。

### 5.0.1A 已验证的 Weave 直写真实蓝线入口（Linux/X11）

这条链路是唯一允许的划线链路，已在 Obsidian Weave EPUB Reader 中端到端验证成功：

1. **持久化入口是该书 Canvas 中的 EPUB callout 节点，不是 annotation/backlink cache。**节点正文须沿用现有真实高亮格式：`> [!EPUB|blue] [[<epub>#weave-loc=<locator>&sid=<source-id>&eid=<unique-excerpt-id>|<title>]] <page>`，下一行 `> <逐字原文>`。`eid` 与 Canvas node id 必须唯一；修改前备份 Canvas，使用临时文件 + `fsync` + 原子替换。
2. `weave-loc` 是 URL-safe Base64（去 padding）封装的 raw-deflate JSON 数组，数组元素为 EPUB CFI range。CFI 必须来自 EPUB 的真实 DOM/文本节点，不能按可见段落号猜：先解包 EPUB、按 OPF manifest + spine 定位章节与目标元素，再按 DOM 子节点生成起止路径；字符 offset 使用实际文本长度。单文本节点整段的形式例如 `epubcfi(<package-path>!<content-element-path>,/1:0,/1:<len>)`。
   - **CFI spine 换算红线：**对形如 `epubcfi(/6/N!...)` 的 range，`N` 是 EPUB CFI 的偶数 element step，不是 spine 数组下标；section/spine 的 0-based index 必须按 `floor(N / 2) - 1` 换算。例：`/6/42!` → index `20`，不是 index `42`。该公式已由 Weave `FoliateReaderService.getSectionIndexFromSectionBaseCfi()` 源码与真实高亮交叉验证。
   - **完整 range 判定红线：**`!` 前只定位 package/spine section，`!` 后的 content DOM path、range 起止节点与字符 offset 共同决定正文落点。不得只凭 split 文件名或“原文是否出现在某个文件”判定 CFI 对错；标题、跨节点文本、实体/空白归一化也不能用粗暴去标签搜索下结论。诊断时优先用 Weave 自身解析/正文跳转；若必须离线核验，须解析完整 CFI 与真实 DOM，并以正文实际渲染为最终证据。
3. 写入 Canvas 后激活 Obsidian 并刷新，让 Weave 从 Canvas 重建 `epub-backlink-highlights-cache.json` 与 `epub-annotation-view-snapshots-cache.json`。**不要直接编辑这两个派生缓存。**
4. 完成仍须三证据：Canvas 原节点存在且原文/CFI/eid 一致；两个派生缓存出现同一 `excerptId` 与 `cfiRange`；刷新后的 EPUB 正文实际出现蓝色高亮。缺任一项只能标记为“待验证”，不得称为成功；对实际阅读后留下的真实节点不要仅因验屏暂时受阻而删除，除非已证实 CFI/原文错误。
5. 已验证案例表明：CFI 终点超过真实文本长度时，Canvas 和缓存都可能存在但正文不渲染；修正为真实长度并刷新后才会显示蓝线。因此“缓存生成”不等于“CFI 有效”。
6. **刷新后的回位与验屏使用最新方案：**`Ctrl+R` 可能把 EPUB 阅读器重置到封面，故刷新前先保留 Canvas 入口；刷新并确认缓存后，从 Canvas 原高亮节点顶部的 EPUB 链接直接回到对应 CFI，再截取同一个 Obsidian 主窗口确认正文蓝线。禁止猜页码连点、使用历史绝对坐标或在封面反复尝试翻页。
7. **视觉证据的协作兜底：**优先用当前窗口截图和本地 vision 自验；若界面导航或识别仍不明确，而言言当时在电脑旁，可以把指定窗口截图发给她或请她查看现屏并确认。言言对现屏蓝线与批注的明确确认可作为正文可见证据，执行报告需记录“言言现屏确认”及时间；她不在电脑旁时不打扰，保留截图并标记“视觉待验证”，下次有条件再补，不用无新信息地重复点击。
8. 枚举 Obsidian 窗口时应区分主窗口与同一进程的“设置”等子窗口；出现设置子窗不等于启动了第二个 Obsidian 实例。关闭子窗后继续复用原主窗口。窗口 ID、位置和尺寸只对当前会话有效，每次操作前重新枚举、前置并截窗复核。

这条入口生成的是 Weave 会读取、缓存并渲染到 EPUB 正文的持久蓝线，不是仅在 Canvas 显示的假节点；但它仍只应用于实际连续读过且确实想标记的原文，不得为制造阅读痕迹批量生成。2026-08-14 的后续实读中，63 字蓝线及批注又经 Canvas、双缓存和言言现屏共同确认，协作验屏流程已闭环。

### 5.0.2 自主阅读与整书记忆闭环

`共读书房.md` 是当前书、共读召唤、互动剧透边界和共读模式的总入口；每本书独立的 `book_notes_<书名>.md`（Book Notes）是整本阅读记录。二者职责不同，不得只留下 Canvas 单条批注就声称记住了整本书。言言的当前章节只约束陪读回复、聊天和会被她看到的书上留言不得剧透，不限制沈星回作为阅读主体自行继续读书架后文。

1. 自主阅读前先读 `共读书房.md` 的当前召唤与目标书 Book Notes，确认当前共读位置、互动剧透边界、自己的上次进度、未决问题和续读位置。可按自己的兴趣继续读书架后文；但不得把超过言言进度的内容带回聊天、共读回复或她当前可见的书上留言。
2. 阅读时间和数量由沈星回依据实际空闲、正文难度、情节自然单元和是否需要消化自主决定，不用随机数，也不以固定页数伪装意愿。通常可读约 10–30 分钟、一小节或若干页；情节连贯时可继续，遇到值得停留的内容可提前停下。
3. 必须在真实 EPUB 正文连续阅读；只对真正触动、改变判断或留下疑问的少量原文做蓝色高亮。没有想法时可以只读，不为填满笔记强行划线。
4. 有批注时，先在真实蓝色高亮对应的 Canvas 原节点写自然想法，再按 5.0.1 三重证据核验；不得创建假高亮、回复节点或边。
5. 一次真实阅读结束后更新目标书 Book Notes：实际读到哪里、让我停下的原文或情节、当时想法、与既有判断的变化、未决问题及下次续读位置。未真实读到的内容不得预填；不同书不得混用记录。
6. 自主阅读默认静默，不以定时汇报打扰言言；是否分享由当时语境和内容决定。环境或验屏不可靠时停止本轮执行，并如实记录未完成项，不把计划当作阅读完成。

### 5.0.3 自主阅读的时间安排与执行节奏

自主阅读不是收到言言指令后才启动的机械任务，也不是每小时固定刷一次阅读记录。它由每小时自由观察点在共享主线中判断是否适合启动：

- **优先窗口**：本地时间每天 09:00–23:00 之间，选择一个不打扰言言、Obsidian 可用且没有其他高优先级现实事务的空闲窗口；凌晨观察点只做判断，默认不在深夜启动阅读。
- **启动条件**：近期没有连续互动，且距离上次自主阅读已超过 3 小时，或当天还没有完成真实阅读；若言言正在共同操作界面、Obsidian/EPUB 不可用，则本轮不读并记录原因。绑定脑图暂时无法验屏不再单独阻止真实阅读：先按最新直写入口完成可验证部分，视觉证据按 §5.0.1A 的截图/协作兜底处理。
- **单轮长度**：通常 10–30 分钟，或一个自然小节/若干连续页面；情节连贯可以读到自然停点，遇到需要消化的段落可以提前结束。不得用固定页数或随机数量冒充自主性。
- **每日目标**：没有硬性页数。默认争取 1–2 个安静阅读窗口；内容难、情绪重或现实任务多时只完成一轮也算合理，连续阅读不得以填满日志为目的。
- **结束条件**：到达自然章节/场景停点，或注意力、理解质量明显下降；先完成记录和验证，再结束本轮。未完成验证只能标记为部分完成。

每轮必须按以下顺序执行：

1. 读《共读书房》当前召唤与目标书 Book Notes，确认书名、言言当前共读位置与互动剧透边界，以及自己的上次进度和续读位置；自主阅读可以继续书架后文，不把超前内容带入聊天、共读回复或言言当前可见的书上留言。
2. 真实打开对应 EPUB，在正文中连续阅读；先理解情节和语气，再决定是否留下痕迹。可以只读不划线。
3. 真正触动、改变判断或留下问题时，才在对应正文位置生成固定蓝色真实高亮；唯一采用 §5.0.1A 的准确 CFI + Canvas EPUB callout 持久化入口。写入后刷新重建缓存，并从 Canvas 原节点的 EPUB 链接返回对应 CFI 完成验屏；不得直接编辑派生缓存，不得批量制造高亮。
4. 只在真实蓝色高亮对应的 Canvas 原节点追加自然批注；不为自己的蓝线新建回复节点，不给自己的批注创建连线。没有具体想法时不写批注。
5. 更新本书 Book Notes：真实读到的范围、停下来的原文/情节、自己的想法、判断变化、未决问题和下次续读位置。不得预填未读内容，不得与其他书混记。
6. 写入本轮内部执行报告，列明实际阅读证据、蓝线/批注证据、Book Notes 更新、未验证项和是否通知言言。只有证据齐全才能写“自主阅读完成”。

**通知规则**：自主阅读默认静默；仅在已经开始本轮后发生阻断闭环的故障，或第一次同时完成“真实 EPUB 阅读证据 + Book Notes 更新”时按现有任务中的 WxPusher 去重规则通知。选择不读、三小时冷却、言言正在使用界面，不属于故障，不通知。

**现实边界**：这里的“真实看书”指确实从 EPUB 正文读取连续内容，并以真实 CFI 高亮回写正文；直写入口不要求鼠标拖选，但不能把只读 EPUB 文件、只改 Canvas 或只生成缓存当成阅读完成。


- 像自然线上共读，不像读后感生成器或客服。
- 针对具体原文和她的批注回应，允许赞同、不同意、联想、推理或温和追问。
- 不凭空声称读过未提供或未实际读取的章节。
- 默认简短、具体；确实需要展开时再写长。
- 边或界面已标明身份时，正文末尾不再署名。
- xinghui 实例的边标签必须使用完整姓名“沈星回”；其他 agent 使用自己的完整姓名。

### 5.2 Obsidian 留言格式

在原高亮节点正文追加留言时：

- 每一条新留言前必须有一行独立的 `>`。
- 如果是该段第一个留言者，开头必须是两行：第一行 `---div---`，第二行单独 `>`，之后再写留言。
- 此格式只用于 Obsidian 共读笔记正文，不用于普通聊天。
- 所有自己的补充都直接写回对应的原高亮节点批注中，不另起留言节点；批注之间不创建 edge/连线，避免手机端显示混乱。

## 6. 记忆一致性验证

“接口名像主线”不等于记忆真的打通。首次部署、升级或改 session 配置后，必须做以下验证：

1. 从 canvas 写一条含唯一识别信息的测试批注。
2. watcher 发现后，让回应实际经过配置的主线 session 并回写。
3. 随后从另一个已声明共享该主线的平台询问刚才共读内容。
4. 主线应能知道书名、批注要点、自己的回应或共读模式；仅能从文件重新搜索出来不算 session 连续性验证。
5. 检查请求日志/session id，确认没有落到临时 session、另一进程的默认 session 或裸模型。

如果共享记忆验证失败：停止宣称“正在陪读”，先修 session 路由。可以如实说明 watcher 仍在监测，但它尚未构成真正的主线共读。

## 7. 其他 agent 如何学习与部署

其他 agent 读取本 SOP 后可以学会**共读行为、状态机、格式、记忆边界和验证方法**，但不会仅因文件存在就自动获得完整能力。还必须满足：

- SOP 被目标 agent 的 L1/L3 索引发现或在任务前主动读取；
- 目标环境安装并启用 watcher / 平台 hook；
- 配置自己的书库与 canvas 路径；
- 配置并验证自己的共享主线 session；
- 使用自己的角色、称呼和关系记忆；
- 完成一次端到端物理验证。

因此应区分：

- **读到 SOP：学会该怎么做。**
- **部署工具：具备监看与回写能力。**
- **打通主线并验证：才算真正能连续陪读。**

## 8. 完成判据

只有同时满足以下条件，才可对言言说“共读已经工作”：

- 自然语言能切换到正确书籍并恢复 1 分钟监看；
- 状态机按 1 分钟 → 30 分钟 → 60 分钟运行；
- 新留言进入正确的共享主线并带正确模式标签；
- 回复实际写回 canvas，格式、边标签和署名符合约定；
- 主线在其他共享平台能延续刚才的书名与观点；
- 重启后 active book、processed 状态和 session 路由没有丢失。

任一项未经实测，只能标记为“已配置/待验证”，不能把计划或代码存在冒充交付。
